# 実装済みの機能一覧

READMEでは主な機能だけを紹介しています。このページには、実装済みの機能をすべて載せています。

## 求人票の管理

- 求人票の登録・閲覧・編集・削除
- 自動分析、メモ、応募状況の変更、変更履歴をまとめた詳細画面
- 原文の抜粋と固定残業代のバッジを載せた、カード形式の一覧
- 応募状況による絞り込みと変更
- ページ送りと並べ替え
- 求人票ごとのメモの登録・編集・削除
- 応募締切の登録と編集
- 応募状況の変更履歴（自動で再読み込み。求人票ごとに最新100件まで）
- 応募状況ごとの件数集計（GROUP BYを使った1回のクエリ）
- 初めての登録の流れ：登録後に通知付きで詳細画面を開き、一覧が空のときは使い方を案内する
- 原文の文字数カウンター（上限を超えたら、下書きを切り詰めずに送信を止める）
- 画面ごとのページタイトル（詳細画面のタイトルには求人名を入れない）

## 求人票の分析（ルールベース）

- 貼り付けた原文を見出しごとの区間に分け、求人サイトが末尾に付ける他の求人を無視する
- 固定残業代の有無と時間数を、根拠の行と一緒に判定する。「記載なし」と「判定できず」を区別する
- 技術スタックを辞書から抽出し、「必須」「歓迎」「応募資格に記載（必須・歓迎の記載なし）」「判定できず（記載が矛盾）」「その他の記載」に分ける
  - 否定の表現（「不問」など）と「いずれか」の選択を扱う
  - 根拠の行を、区間名と一緒に示す
- 根拠を原文の中で強調表示する（「原文で見る」）
- 分析結果は保存せず、表示のたびに保存済みの原文から計算する

## 検索と絞り込み

- キーワード検索
- 月給の範囲による絞り込みと入力チェック
- 応募締切の範囲による絞り込みと入力チェック
- 締切の範囲が逆のときは、検索リクエストを送る前に止める
- 詳細検索の画面
- PostgreSQLの `pg_trgm` とGINインデックスによる検索の高速化

## 認証と認可

- メールアドレスによる会員登録・ログイン・ログアウト
- Spring Session JDBCによるセッション認証
- SPA向けのCSRF対策
- ユーザーごとの求人票の所有権（他のユーザーの求人票は404を返す）
- ブラウザのタブ間でのログイン状態の同期
- ログイン中のユーザーが変わったときの画面のリセット
- パスワード確認付きの退会

## セキュリティとエラー処理

- NginxによるIPアドレスごとのリクエスト数の制限（レート制限。ログイン、会員登録、退会、書き込みAPI）
- Nginxによるリクエストサイズの制限
- Content Security Policyを含むセキュリティヘッダー
- 求人票の元URLはhttpとhttpsだけを受け付ける
- 求人票・メモ・変更履歴のユーザーごとの保存上限と、全体のユーザー数の上限
- 形式をそろえたJSONのエラーレスポンス
- SQLStateに基づくデータベースエラーの変換

## 同時編集とAPIの一貫性

- JPAの `@Version` による楽観的ロック
- ETagとIf-Matchによる条件付き更新（求人票の編集・応募状況の変更・メモの編集）
- メモの編集が競合したときの、入力の保持と最新の内容の表示
- 不正な形式のIf-Matchヘッダーのチェック
- flush時に起きる楽観的ロックの競合の処理

## フロントエンドの信頼性

- `AbortController` による、分析の古いレスポンスの無視
- 一覧の古いレスポンスの無視
- 一覧と入力中の内容を画面に残したままの、メモと履歴の再読み込み
- メモの変更の再試行
- メモの保存の古いレスポンスの無視
- 描画のたびに新しい取得関数が渡されても、再取得を繰り返さないデータ取得フック
- すべての検索条件（キーワード、応募状況、月給、締切、並べ替え、ページ）をURLのクエリに保持し、不正な値は無視する
- ブラウザの戻る・進むと、詳細画面から戻ったときの検索条件の復元
- ページ番号が範囲外になったときの補正
- 編集中の保護と、バージョン競合が起きた後の復旧
- 登録・編集フォームの項目ごとのエラー表示
- セッションが切れても登録・編集・メモの入力内容を残し、ログアウトやユーザーの切り替えで消す

## テストとCI

- バックエンドとフロントエンドの回帰テスト
- TestcontainersによるPostgreSQLの結合テスト
- 楽観的ロックの結合テスト
- リクエストの入力チェック、項目ごとのエラー表示、件数集計の独立した読み込みの回帰テスト
- 求人票の分析の判定規則のテスト（固定残業代、必須・歓迎スキル）
- Docker Composeのスモークテスト
- GitHub ActionsによるCI
