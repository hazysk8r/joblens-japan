# Dockerスモークテストの接続エラー

`docker-smoke.sh check`はホストのPythonから、CI専用Composeの公開ポートに接続する。

Windowsのローカル実行では、`socket.connect()`が`WinError 10014`(`WSAEFAULT`)で
失敗することがある。原因は特定できていない。

確認できていること:

- HTTP要求を送る前の失敗で、失敗した要求はNginxのログに残らない。
- Nginxの`/healthz`へのGETだけでも起きるため、バックエンドやDB、POSTは必要ない。
- 起動直後に限らず、ある時間に集中して起きる。起きない時間も長いため、
  数回の通過だけでは解消したと判断できない。

要求ごとに新しい接続を作るため、失敗する箇所は実行のたびに変わる。

`10014`で失敗したときは、スタックを作り直して再実行する。機能の確認はUbuntuのCIを基準にする。
スモークのためにアプリの設定を変更する必要はない。

詳細なスタックトレースは、既存のCI用環境変数を設定した状態で次のように取得する。

```bash
SMOKE_DEBUG=1 bash scripts/ci/docker-smoke.sh check
```

Pythonを直接実行する場合は`--debug`を付ける。通常のログにも例外の種類と
`errno`・`winerror`を残すため、HTTPエラーとソケットエラーを区別できる。
接続・送信・応答読み取りの失敗は即座に失敗とし、POSTを自動再送しない。

`check`は会員登録や求人作成を行い、最後にDBのコンテナを止める。
再実行するときは`cleanup`と`start`で、新しいCI専用のスタックを作る。
